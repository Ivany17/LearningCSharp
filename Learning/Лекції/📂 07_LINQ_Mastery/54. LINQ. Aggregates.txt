Тема №54. LINQ: Метод .Aggregate()
Теорія:
Суть методу полягає у поступовому накопиченні результату. Він бере два перші елементи списку, 
робить із ними якусь дію, отримує результат, а потім бере цей результат і наступний (третій) елемент списку. І так до кінця.

У Aggregate є три основні компоненти:
Накопичувач (Accumulator (acc) / seed): змінна, яка зберігає проміжний результат.
Поточний елемент (Item (n)): наступне значення зі списку.
Логіка: вираз, який каже, як саме поєднати накопичувач і поточний елемент.

📒 Шпаргалка по LINQ .Aggregate()
Метод має три основні форми (перевантаження). Вибирай ту, яка підходить під твою задачу.

1. Проста форма (без seed)
Використовується, коли результат має той самий тип, що й елементи масиву.
Як працює: бере 1-й елемент як старт, і починає цикл з 2-го.
Приклад: numbers.Aggregate((acc, n) => acc + n);

⚠️ Ризик: Видасть помилку InvalidOperationException, якщо список порожній.

2. Форма з початковим значенням (with seed)
Найпопулярніша форма. Дозволяє безпечно працювати з порожніми списками та змінювати тип результату.
Як працює: acc спочатку дорівнює seed, цикл іде по всім елементам.
Приклад: codes.Aggregate("Errors:", (acc, n) => acc + "-" + n);
Плюс: Якщо список порожній, повернеться просто seed.

3. Повна форма (with resultSelector)
Використовується, коли після всіх обчислень потрібно зробити "фінальний штрих".
Структура: .Aggregate(seed, accumulator, resultSelector)
Приклад: .Aggregate(0.0, (acc, n) => acc + n, res => $"Total: {res}");
Плюс: Дозволяє винести логіку форматування або округлення прямо в запит.

💡 Коли використовувати Aggregate замість Sum/Min/Max?
Складна логіка: Коли треба не просто додати, а, наприклад, помножити або застосувати умови.
Декілька значень за раз: Обчислення суми та кількості одночасно через анонімний об'єкт.
Трансформація структур: Перетворення списку в словник або довгий рядок за особливим правилом.

Крок №1: "Елементарне додавання"
Мета: Зрозуміти, як працює найпростіша форма Aggregate без початкового значення.
Коли ми не вказуємо «початкове значення» (seed), Aggregate бере перший елемент масиву як початковий acc і починає роботу з другого елемента.

📝 Завдання №54:
Створи список чисел int[] numbers = { 1, 2, 3, 4, 5 };.
Використай .Aggregate((acc, n) => => ... ), щоб отримати суму всіх чисел.
Підказка: На кожному кроці ти просто додаєш поточне число (n) до того, що вже накопичено (acc).

✅ Рішення:
int[] numbers = { 1, 2, 3, 4, 5 };
var sum = numbers.Aggregate((acc, n) => acc + n);
Console.WriteLine(sum); // 15

Крок №2: "Пошук екстремуму"
Тепер давай використаємо Aggregate для того, що зазвичай роблять методи Max або Min. Це допоможе зрозуміти, що 
всередині ми можемо не тільки додавати, а й ставити умови.
В цьому випадку ми все ще не використовуємо seed (початкове значення), тому перший елемент масиву автоматично стає першим "кандидатом" на максимум.

Завдання:
У тебе є той самий масив: int[] numbers = { 1, 2, 3, 4, 5 };.
Напиши Aggregate, який знайде найбільше число в масиві.
Логіка: Порівняй acc (найбільше, що ми бачили до цього моменту) та n (поточне число). Результатом кроку має стати те з них, яке більше.

✅ Рішення:
int[] numbers = { 1, 2, 3, 4, 5 };
var maxNum = numbers.Aggregate((acc, n) => acc > n ? acc : n);
Console.WriteLine(maxNum); // 5

Крок №3: "Робота з текстом (Конкатенація)"
Aggregate працює не тільки з числами. Це один із найшвидших способів склеїти масив рядків у складне речення, якщо string.Join здається занадто простим.

Завдання:
Створи масив: string[] words = { "C#", "is", "awesome", "and", "powerful" };.
Використай Aggregate, щоб склеїти ці слова в одне речення, розділяючи їх пробілом.
Логіка: До накопичувача acc (який спочатку буде словом "C#") додавай пробіл та наступне слово item (n).
Для довідника: Зверни увагу, що в результаті у тебе не повинно бути зайвого пробілу на самому початку або в самому кінці. 
Aggregate без початкового значення (seed) тут дуже зручний, бо він почне з першого слова і не додасть пробіл перед ним.

✅ Рішення:
string[] words = { "C#", "is", "awesome", "and", "powerful" };
var phrase = words.Aggregate((acc, n) => acc + " " + n);
Console.WriteLine(phrase); // C# is awesome and powerful

Крок №4: "Початкове значення (Seed)"
У цьому перевантаженні ми додаємо перший аргумент — seed. Це значення, яке acc приймає ще до того, як подивиться на перший елемент масиву.

Завдання:
У тебе є список денних витрат енергії: double[] dailyUsage = { 10.5, 12.0, 8.5 };.
Потрібно порахувати загальну суму, але врахувати базове споживання, яке вже було на лічильнику на початку дня — 100.0.
Використай .Aggregate(100.0, (acc, n) => ... ).
Для довідника: Використання seed робить твій код безпечнішим. Якщо масив dailyUsage буде порожнім, 
Aggregate просто поверне значення seed (100.0) і не видасть помилку.

✅ Рішення:
double[] dailyUsage = { 10.5, 12.0, 8.5 };
var usage = dailyUsage.Aggregate(100.0, (acc, n) => acc + n);
Console.WriteLine(usage); // 131

Крок №5: "Зміна типу даних (The Transformation)"
Це один із найпотужніших прийомів. Aggregate дозволяє почати з одного типу (наприклад, чисел), а закінчити зовсім іншим (наприклад, текстом).

Завдання:
Маємо список кодів помилок: int[] errorCodes = { 404, 500, 403 };.
Потрібно створити один рядок, який починається зі слова "Errors:", а далі через дефіс перераховує всі коди.
Seed (початкове значення) тут має бути рядком: "Errors:".
Підказка по логіці:
Тепер твій acc — це рядок (String), а n — це число (Int). На кожному кроці ти додаєш до рядка дефіс та поточне число.
Для довідника: Оскільки ми вказали seed як рядок "Errors:", то і весь результат Aggregate автоматично стане рядком. Це і є трансформація типів.

✅ Рішення:
int[] errorCodes = { 404, 500, 403 };
var errors = errorCodes.Aggregate("Errors:", (acc, n) => acc + "-" + n);
Console.WriteLine(errors); // Errors:-404-500-403

Крок №6: "Вибіркова агрегація (Логіка всередині)"
Aggregate може не просто збирати все підряд, а й фільтрувати або змінювати дані «на льоту» без використання додаткового .Where().
Цей підхід часто ефективніший за ланцюжок .Where(...).Sum(), оскільки виконується за один прохід по масиву.

Завдання:
Маємо список балів: int[] scores = { 50, 65, 40, 80, 20 };.
Потрібно порахувати суму тільки тих балів, які більші за 45.
Seed (початкове значення) обов’язково має бути 0 (оскільки ми рахуємо суму чисел).

Підказка по логіці:
Всередині лямбда-виразу тобі потрібно перевірити: якщо n > 45, то додати його до acc. 
Якщо ні — просто повернути поточний acc без змін, щоб він чекав на наступне число.

✅ Рішення:
int[] scores = { 50, 65, 40, 80, 20 };
var bestScores = scores.Aggregate(0, (acc, n) => n > 45 ? acc + n : acc);
Console.WriteLine(bestScores); // 195

Крок №7: "Агрегація об'єктів (Властивості)"
Тепер попрацюємо з твоїми класами Apartment. Це саме той випадок, який найчастіше зустрічається в реальних проєктах.
Хоча для цього є метод .Sum(x => x.EnergyConsumption), розуміння того, як це робить Aggregate, 
дозволить тобі в майбутньому робити набагато складніші розрахунки (наприклад, множення або складні формули) за один прохід.

Завдання:
Тобі потрібно обчислити загальну кількість спожитої енергії по всьому масиву myBuildings, 
використовуючи лише один рядок з .Aggregate().

Логіка для твого запису:
Seed: Починаємо з 0.0 (оскільки ми рахуємо суму значень double).
Lambda: На кожному кроці ти береш те, що вже накопичено в acc, і додаєш до нього значення n.EnergyConsumption.

✅ Рішення:
var myBuildings = new[]
{
    new { Name = "Apartment #1", EnergyConsumption = 50.5 },
    new { Name = "Apartment #2", EnergyConsumption = 30.0 },
    new { Name = "Apartment #3", EnergyConsumption = 20.5 }
};

var consumption = myBuildings.Aggregate(0.0, (acc, n) => acc + n.EnergyConsumption);
Console.WriteLine(consumption); // 101

Крок №8: "Подвійна агрегація (Анонімні об'єкти в Seed)"
Що, якщо нам потрібно порахувати дві різні речі за один прохід? Наприклад, і загальну суму енергії, 
і кількість квартир. Aggregate дозволяє використовувати анонімний об'єкт як seed.
Це "золотий стандарт" продуктивності. Замість того, щоб два рази перебирати список (через .Sum() та .Count()), ти робиш все за один цикл.

Завдання:
Використовуй той самий масив myBuildings.
Створи Aggregate, де seed — це анонімний об'єкт з двома полями: TotalEnergy = 0.0 та Count = 0.
У лямбда-виразі на кожному кроці створюй новий анонімний об'єкт, де:
1. TotalEnergy збільшується на n.EnergyConsumption.
2. Count збільшується на 1.

✅ Рішення:
var myBuildings = new[]
{
    new { Name = "Apartment #1", EnergyConsumption = 50.5 },
    new { Name = "Apartment #2", EnergyConsumption = 30.0 },
    new { Name = "Apartment #3", EnergyConsumption = 20.5 }
};

var energy = myBuildings.Aggregate(new {TotalEnergy = 0.0, Count = 0}, (acc, n) => new
                                        {
                                            TotalEnergy = acc.TotalEnergy + n.EnergyConsumption,
                                            Count = acc.Count + 1
                                        });
Console.WriteLine(energy); // { TotalEnergy = 101, Count = 3 }

Крок №9: "Агрегація у словник (Building a Dictionary)"
Тепер давай зробимо щось дійсно складне. Ми використаємо Aggregate, щоб перетворити список об'єктів на Dictionary (словник), 
де ключем буде назва квартири, а значенням — її енергоспоживання.
Хоча для цього є метод .ToDictionary(), використання Aggregate дає тобі повний контроль. 
Наприклад, ти міг би додати логіку, яка ігнорує дублікати або підсумовує значення для однакових ключів прямо під час створення словника.
Ти використав Aggregate як конструктор складних структур. Це критично важливо, коли стандартні методи LINQ (як .ToDictionary()) 
не дають достатньо гнучкості (наприклад, якщо у списку можуть бути однакові назви квартир і ти хочеш їх підсумувати, а не отримати помилку).

Завдання:
Використовуй масив myBuildings.
Seed: Новий порожній словник new Dictionary<string, double>().
У лямбда-виразі на кожному кроці додавай поточний елемент у цей словник.
Підказка по логіці:
На відміну від попередніх кроків, тут ми не створюємо новий об'єкт через new, 
а змінюємо існуючий acc (наш словник) і обов'язково повертаємо його в кінці лямбди.

✅ Рішення:
var myBuildings = new[]
{
    new { Name = "Apartment #1", EnergyConsumption = 50.5 },
    new { Name = "Apartment #2", EnergyConsumption = 30.0 },
    new { Name = "Apartment #3", EnergyConsumption = 20.5 }
};

var dictionary = myBuildings.Aggregate(new Dictionary<string, double>(), (acc, n) => 
                                        {
                                            acc.Add(n.Name, n.EnergyConsumption);
                                            return acc; 
                                        });
foreach (var kvp in dictionary)
{
    Console.WriteLine($"Квартира: {kvp.Key} | Споживання: {kvp.Value}");
    // Квартира: Apartment #1 | Споживання: 50,5
    // Квартира: Apartment #2 | Споживання: 30
    // Квартира: Apartment #3 | Споживання: 20,5
}

Крок №10: "Фінальний бос — Повна трансформація з результатом (Result Selector)"
У Aggregate є третя, найбільш повна форма. Вона дозволяє в кінці всього процесу виконати 
фінальну дію над накопиченим результатом (наприклад, округлити його або перетворити на інший тип).
Третій параметр (resultSelector) зручний тим, що він дозволяє "закрити" обчислення всередині методу, 
видаючи назовні вже готовий до використання об'єкт або рядок.

Завдання:
Використовуй масив myBuildings.
Порахуй суму енергії (як у кроці №7), але додай третій аргумент у метод Aggregate.
Цей третій аргумент — лямбда, яка приймає фінальний acc і каже, що з ним зробити.

✅ Рішення:
var myBuildings = new[]
{
    new { Name = "Apartment #1", EnergyConsumption = 50.5 },
    new { Name = "Apartment #2", EnergyConsumption = 30.0 },
    new { Name = "Apartment #3", EnergyConsumption = 20.5 }
};

var resultSelector = myBuildings.Aggregate(0.0, (acc, n) => acc + n.EnergyConsumption, finalSum => $"Final Energy Report: {finalSum} kWh");

Console.WriteLine(resultSelector); // Final Energy Report: 101 kWh
