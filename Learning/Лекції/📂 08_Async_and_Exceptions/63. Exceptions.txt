Тема №63: Обробка винятків (Exceptions) 🛡️
Ти вже вивчав цю тему на уроцы №44, коли вивчав JSON, але на цей раз ми розглянемо винятки набагато детальніше
У програмуванні виняток (Exception) — це ситуація, коли під час виконання програми стається щось непередбачуване, 
що змушує її негайно припинити роботу (краш). Наприклад: спроба поділити на нуль, відкрити відсутній файл або перетворити текст "Привіт" на число int.

1. Конструкція try...catch 🧱
Щоб програма не "падала", ми використовуємо блок-запобіжник:
try: сюди ми кладемо код, який потенційно може видати помилку.
catch: цей блок спрацює тільки якщо в блоці try сталася помилка. Тут ми описуємо, як програма має на це відреагувати 
(наприклад, вивести ввічливе попередження замість вильоту).

2. Типи помилок (Класи Exception) 🏷️
C# має багато вбудованих типів помилок, щоб ми могли реагувати на них по-різному:
FormatException: стається, коли ми намагаємося перетворити рядок у невідповідний формат (наприклад, int.Parse("abc")).
DivideByZeroException: спроба ділення на нуль.
OverflowException: якщо число занадто велике для обраного типу даних.
Exception: "базова" помилка. Вона ловить абсолютно все.

3. Блок finally 🏁
Існує також третій блок — finally. Він виконується завжди, незалежно від того, була помилка чи ні. Зазвичай там закривають файли або звільняють ресурси.

📝 Завдання №63.1: "Броньований калькулятор" 🧮
Давай створимо програму, яка не "помре", навіть якщо користувач введе повну нісенітницю.
Попроси користувача ввести ціле число.
Використай int.Parse(Console.ReadLine()), щоб отримати значення.
Огорни цей код у try...catch:
У блоці try: якщо все пройшло успішно, виведи повідомлення: "Число {число} прийнято до обробки!".
У блоці catch (FormatException): виведи повідомлення: "Помилка: Ви ввели текст замість числа!".
У блоці catch (Exception): (універсальний ловушка) виведи: "Сталася якась інша помилка!".
Обов'язково: після блоку catch виведи в консоль: "Програма продовжує роботу...", щоб довести, що вона не "вилетіла".

✅ Рішення:
Console.WriteLine("Введіть, будь ласка, ціле число");

try
{
    int answer = int.Parse(Console.ReadLine()!);
    if(answer > 0)
    {
        Console.WriteLine($"Число {answer} прийнято до обробки!");
    }
} catch (FormatException)
{
    Console.WriteLine("Помилка: Ви ввели текст замість числа!");
} catch (Exception)
{
    Console.WriteLine("Сталася якась інша помилка!");
}
Console.WriteLine("Програма продовжує роботу...");

📝 Завдання №63.2: "Асинхронний запобіжник" ⚡
Давай поєднаємо твій досвід із завантаженням файлів та нову навичку обробки помилок.
Умова:
Створи асинхронний метод DownloadDataAsync().
Усередині методу імітуй помилку: замість затримки просто напиши рядок throw new Exception("З'єднання з сервером розірвано!");. 
Це примусово викличе "вибух" у програмі.
У основному коді (Program.cs):
Виклич цей метод через await.
Огорни виклик у блок try..catch.
У блоці catch виведи повідомлення: "Сталася помилка завантаження: " + ex.Message.

✅ Рішення:
try
{
    await DownloadDataAsync();

    async Task DownloadDataAsync()
    {
        await Task.Delay(500); // додаємо цей рядок, щоб зникло жовте попередження
        throw new Exception("З'єднання з сервером розірвано!");
    }
} catch (Exception ex)
{
    Console.WriteLine($"Сталася помилка завантаження: {ex.Message}");
}

📝 Завдання №63.3: "Фільтрація помилок" 🎯
Давай зробимо твій catch ще професійнішим. Уяви, що ми хочемо по-різному реагувати на різні проблеми.
Умова:
Залиш метод DownloadDataAsync, але змініть його так, щоб він кидав не загальний Exception, 
а HttpRequestException (це спеціальна помилка для проблем з інтернетом).
Код: throw new HttpRequestException("404: Сервер не знайдено");
У Program.cs зроби два блоки catch:
Перший: catch (HttpRequestException ex) — виведи: "Помилка мережі: {ex.Message}".
Другий: catch (Exception ex) — виведи: "Невідома помилка: {ex.Message}".

✅ Рішення:
try
{
    await DownloadDataAsync();

    async Task DownloadDataAsync()
    {
        await Task.Delay(500);
        throw new HttpRequestException("404: Сервер не знайдено");
    }
} catch (HttpRequestException ex)
{
    Console.WriteLine($"Помилка мережі: {ex.Message}");
} catch (Exception ex)
{
    Console.WriteLine($"Невідома помилка: {ex.StackTrace}"); // StackTrace показує де саме і на якому рядку сталася помилка
}

📝 Завдання №63.4: "Стійка система" 🏗️
Створи два методи:
GetWeatherAsync(): затримка 1000 мс, повертає Task<string> із текстом "Сонячно, +25°C".
GetNewsAsync(): затримка 2000 мс, але замість повернення результату він має викинути помилку Exception із текстом "Сервер новин не відповідає!".
У основному коді (Program.cs):
Запусти обидва методи одночасно (збережи їх у змінні Task).
Огорни виклик await Task.WhenAll(...) у блок try..catch.
У блоці try: після WhenAll виведи результати обох методів.
У блоці catch (Exception ex): виведи повідомлення: "Стався збій у системі: {ex.Message}".

✅ Рішення:
try
{
    Task<string> weather = GetWeatherAsync();
    Task<string> news = GetNewsAsync();

    await Task.WhenAll(weather, news);
    Console.WriteLine(weather.Result);
    Console.WriteLine(news.Result);

    async Task<string> GetWeatherAsync()
    {
        await Task.Delay(1000);
        return $"Сонячно, +25°C";
    }
    async Task<string> GetNewsAsync() // хоч в завданні не вказано тип, краще використати Task<string> для схожості з іншм методом
    {
        await Task.Delay(500);
        throw new Exception("Сервер новин не відповідає!");
    }
} catch (Exception ex)
{
    Console.WriteLine($"Стався збій у системі: {ex.Message}");
}

📝 Завдання №63.5: Лабораторна робота з "підміни" винятків
Тобі потрібно створити програму, яка навмисно використовує різні типи помилок, щоб побачити, хто їх упіймає.
Умова:
Напиши блок try.
Всередині блоку try просто напиши один рядок:
throw new DivideByZeroException("Спеціальна помилка!");
Додай до цього блоку try три блоки catch у такому порядку:
catch (FormatException ex) — нехай виводить: "Це FormatException: " + ex.Message.
catch (DivideByZeroException ex) — нехай виводить: "Це DivideByZeroException: " + ex.Message.
catch (Exception ex) — нехай виводить: "Це загальний Exception: " + ex.Message.
Експеримент:
Запусти програму і подивись, який блок спрацював. (Це підтвердить твою теорію про те, що специфічний catch має пріоритет).
Другий крок: Видали (або закоментуй) блок catch (DivideByZeroException ex) і запустіть програму знову. Подивись, хто впіймає помилку тепер.
Третій крок: Залиш тільки catch (FormatException ex) (видали всі інші) і подивись, що станеться, коли "сітки" для твого типу помилки не залишиться.

✅ Рішення:
try
{
    throw new DivideByZeroException("Спеціальна помилка!");
}
catch (FormatException ex)
{
    Console.WriteLine($"Це FormatException: {ex.Message}");
}
